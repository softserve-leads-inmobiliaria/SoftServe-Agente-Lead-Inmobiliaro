# N-10 — Reporte semanal al gerente por Telegram

**Épica:** E6 · Inteligencia comercial  
**Prioridad:** P2 · **Puntos:** 2 · **Track:** Cross  
**Depende de:** N-6, N-7, A-17

## Historia de usuario

Como gerente, quiero recibir cada semana por Telegram cuánto se colocó, qué está estancado y qué demanda no se cubre, para enterarme sin entrar al panel.

## Criterios de aceptación

- [ ] Un *job* semanal de A-17 manda un mensaje con las colocadas de la semana, las estancadas de más de 60 días y las tres combinaciones más repetidas de demanda insatisfecha.
- [ ] Solo agregados, con el mismo criterio de privacidad que N-8.
- [ ] Destinatario según N-2, con el bot que ya existe.
- [ ] El mensaje enlaza a la vista de N-8.
- [ ] Si Telegram falla, se reintenta en la siguiente ejecución del *job*; no se manda dos veces el mismo reporte.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.
