# CT-4 — Esqueleto end-to-end con los 3 *fakes* conectados

**Épica:** E0 · Contratos y entorno  
**Prioridad:** P0 · **Puntos:** 5 · **Track:** Cross  
**Depende de:** CT-1, CT-2, CT-3, CT-6

## Historia de usuario

Como equipo, quiero conectar los 3 *fakes* (arnés → fake core → fake catalog MCP → respuesta) de punta a punta antes de escribir lógica real, para encontrar bugs de integración cuando arreglarlos cuesta minutos, no semanas.

## Criterios de aceptación

- [ ] Un mensaje de guion entra por el arnés (CT-9) y sale una respuesta fija de punta a punta.
- [ ] Corre con `docker-compose up` en cualquier máquina del equipo, sin configuración adicional.
- [ ] No hay lógica de negocio real todavía — todo el contenido es *fake*, deliberadamente.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas de diseño

Encuentra los bugs de integración (montaje de servicios, transporte de red, *lifespan*) cuando arreglarlos cuesta minutos. Se hace como primer hito real, no como algo que "ya se hará al final".
