# CT-6 — `docker-compose` base

**Épica:** E0 · Contratos y entorno  
**Prioridad:** P0 · **Puntos:** 3 · **Track:** Cross  
**Depende de:** —

## Historia de usuario

Como equipo, quiero un `docker-compose` base (Postgres+pgvector, observabilidad, panel) que levante todo sin nube ni Redis, para desarrollar igual en las 3 máquinas del equipo.

## Criterios de aceptación

- [ ] `docker-compose up` levanta Postgres+pgvector, el servicio de observabilidad elegido, y un panel vacío.
- [ ] Sin Redis — jobs vía el *scheduler* embebido en el `lifespan` de FastAPI (DT-3).
- [ ] Corre igual en Windows/Mac/Linux del equipo; cualquier caveat de Docker Desktop conocido queda documentado en `docs/TESTING.md` apenas se descubre.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.
