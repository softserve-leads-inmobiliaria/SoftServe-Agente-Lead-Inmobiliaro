# N-5 — Campaña de origen y demanda insatisfecha

**Épica:** E6 · Inteligencia comercial  
**Prioridad:** P1 · **Puntos:** 2 · **Track:** A  
**Depende de:** N-1

## Historia de usuario

Como inmobiliaria, quiero saber qué anuncio trajo a cada lead y qué buscan los que no encuentran nada, para medir las campañas y saber qué propiedades captar.

## Criterios de aceptación

- [ ] El `utm_campaign` del evento canónico (`?start=camp_…`, `services/core/app/channels/canonical.py`) se guarda en `leads.utm_campaign` la primera vez que llega. Una campaña posterior no lo pisa: cuenta el primer contacto.
- [ ] Cada `search_properties` con cero resultados escribe una fila en `unmet_searches` con la zona, el tipo, las recámaras y el presupuesto de la búsqueda, sin `lead_id` ni texto del lead.
- [ ] La misma búsqueda repetida dentro de un turno se registra una vez.
- [ ] Las dos escrituras van en la transacción de `advance`.
- [ ] Tests en `services/core/tests` contra Postgres.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.
