# A-6 — Dirección exacta y datos reservados

**Épica:** E1 · Motor del agente  
**Prioridad:** P0 · **Puntos:** 2 · **Track:** A  
**Depende de:** A-5

## Historia de usuario

Como agencia, quiero que la dirección exacta de una propiedad solo se revele a un lead ya calificado, para proteger al propietario y al inventario.

## Criterios de aceptación

- [ ] `address_exact` solo se expone si `lead_qualified=true`, derivado de la banda de score (nunca de lo que pida el LLM).
- [ ] **Guardrail de texto libre incluido en esta misma historia**: detectar una dirección exacta mencionada en prosa aunque no venga del payload (en v1 esto fue C-8, separada y posterior).

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.
- [ ] Gold set de dirección reservada (casos que deben y no deben disparar el guardrail) en verde en CI, 0 fugas.
