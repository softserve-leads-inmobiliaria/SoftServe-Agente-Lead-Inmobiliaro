# CT-5 — Repo, CI y estructura de carpetas

**Épica:** E0 · Contratos y entorno  
**Prioridad:** P0 · **Puntos:** 3 · **Track:** Cross  
**Depende de:** —

## Historia de usuario

Como equipo, quiero el repo, la estructura de carpetas de `docs/ESTRUCTURA-DEL-PROYECTO.md` y el pipeline de CI configurados antes de la primera historia de negocio, para no reorganizar código ya escrito después.

## Criterios de aceptación

- [ ] Estructura de carpetas completa (aunque vacía) según `docs/ESTRUCTURA-DEL-PROYECTO.md`, incluyendo `db/` como paquete compartido desde el primer commit.
- [ ] CI corre lint + tests + contract tests, aunque todavía no haya código real que probar.
- [ ] GitHub Project v2 configurado (labels `epic:*`/`track:*`/`prio:*`, campo `Iteration`).
- [ ] El *workflow* de alta automática de Issues al Project (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5) ya anda desde este commit, no se agrega después.
- [ ] `README.md` raíz existe y enlaza `docs/README.md` desde su primera sección (ver Z-4).

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas para v2 (aprendido en v1)

En v1 el alta al Project era un paso manual sin automatización, causa directa de 2 auditorías de drift (retrospectiva §3.2), y el índice de navegación existió sin enlazarse desde el README raíz hasta el cierre del proyecto (DT-48). Resolver ambos aquí, en la primera historia.
