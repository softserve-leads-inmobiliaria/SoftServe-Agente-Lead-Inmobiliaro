# CT-1 — Congelar el contrato del evento de mensaje canónico

**Épica:** E0 · Contratos y entorno  
**Prioridad:** P0 · **Puntos:** 2 · **Track:** Cross  
**Depende de:** —

## Historia de usuario

Como equipo de desarrollo, quiero un contrato JSON Schema versionado para el evento de mensaje canónico, para que `core`, `catalog` y el arnés de pruebas se construyan en paralelo sin renegociar el formato de los datos a mitad de camino.

## Criterios de aceptación

- [ ] JSON Schema versionado en `contracts/event.schema.json`.
- [ ] Incluye `property_id` y `utm_campaign` como campos opcionales.
- [ ] Al menos un ejemplo válido y uno inválido en `contracts/examples/`.
- [ ] Un test parametrizado en `tests/contracts/` valida ambos ejemplos contra el schema.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas de diseño

Congelar el contrato antes de escribir lógica evita negociar formatos a mitad de camino. La política de versionado quedó fijada en DT-8.
