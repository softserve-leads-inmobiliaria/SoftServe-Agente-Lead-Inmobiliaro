# CT-8 — Fake catalog como servidor MCP en memoria

**Épica:** E0 · Contratos y entorno  
**Prioridad:** P0 · **Puntos:** 3 · **Track:** Cross  
**Depende de:** CT-2

## Historia de usuario

Como equipo, quiero un catalog *fake* servido como servidor MCP real (mismo protocolo que el catalog real usará después) para probar la integración de protocolo sin depender de Postgres.

## Criterios de aceptación

- [ ] ~10 propiedades y 3 asesores en memoria, incluye casos `apartado`.
- [ ] Sirve las 5 tools vía MCP real — servidor en proceso, no un mock genérico. Transporte streamable HTTP montado en `/mcp` (ver `docs/DECISIONS/decisions.md` DT-2), no `stdio`.
- [ ] Versión del SDK de `mcp` pinneada explícita en `requirements.txt` (no un rango) — su API de alto nivel cambia entre versiones mayores.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas de diseño

Fijar la versión exacta del SDK de MCP en este mismo commit y explorar la API realmente instalada antes de codificar: sin versión fija, puede no coincidir con la de los tutoriales (DT-10).
