# A-2 — Respuestas naturales con memoria de conversación

**Épica:** E1 · Motor del agente  
**Prioridad:** P0 · **Puntos:** 3 · **Track:** A  
**Depende de:** A-1

## Historia de usuario

Como lead, quiero que el agente recuerde lo que ya dije en la conversación y pueda consultar el catálogo en tiempo real, para no repetir información y recibir datos actualizados.

## Criterios de aceptación

- [ ] El orquestador arma el prompt con historial leído de Postgres, no de un diccionario en memoria.
- [ ] *Tool calling* real contra el catalog (fake primero, real después).
- [ ] Rate limiting del proveedor de LLM contemplado desde esta historia, no descubierto en producción.
- [ ] **Revisar explícitamente con A-13 si la categoría "cajón de sastre" del clasificador de intención es segura para tener, más adelante, un efecto de sistema real** — no asumirlo.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas de diseño

Fijar el `model_id` exacto y probar una llamada real de un token antes de darlo por bueno en `.env.example`: algunos modelos de Bedrock exigen *inference profile* y el error solo aparece en la primera llamada. El último criterio de aceptación existe para que el traspaso a humano (A-13) no quede sin dueño: se revisa aquí mismo, no cuando falle.
