# C-3 — Esquema de datos completo con migraciones

**Épica:** E3 · Datos y conocimiento  
**Prioridad:** P0 · **Puntos:** 5 · **Track:** C  
**Depende de:** CT-3

## Historia de usuario

Como equipo, quiero el esquema completo de datos (todas las entidades del diseño) con migraciones desde el principio, para que cualquier servicio pueda depender de una tabla real en vez de esperar a que se agregue después.

## Criterios de aceptación

- [ ] Todas las entidades de `docs/DESIGN/design.md` §4.
- [ ] **Incluye la tabla de estado de la FSM desde esta historia** (la que A-1 necesita), no agregada 9 historias después como en v1.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas para v2 (aprendido en v1)
