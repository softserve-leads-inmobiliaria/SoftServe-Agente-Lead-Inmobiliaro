# CT-9 — Arnés de canal

**Épica:** E0 · Contratos y entorno  
**Prioridad:** P0 · **Puntos:** 2 · **Track:** Cross  
**Depende de:** CT-1

## Historia de usuario

Como equipo, quiero un arnés que reproduzca una conversación de guion (`.jsonl` → eventos canónicos) sin depender de Telegram real, para poder probar conversaciones completas desde el primer sprint.

## Criterios de aceptación

- [ ] Formato `.jsonl` documentado.
- [ ] Auto-descubrimiento de fixtures nuevos sin cambios de código.
- [ ] Al menos 2 guiones de ejemplo desde esta historia.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas de diseño

Mantener el arnés creciendo desde el principio: una fixture nueva por cada historia de `core` que cambie el comportamiento conversacional, en vez de posponerlo a un cierre de sprint.
