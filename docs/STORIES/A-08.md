# A-8 — Guardrail de entrada

**Épica:** E1 · Motor del agente  
**Prioridad:** P1 · **Puntos:** 2 · **Track:** A  
**Depende de:** A-1

## Historia de usuario

Como agencia, quiero detectar PII no solicitada, intentos de *jailbreak* y el comando `/stop` antes de que el mensaje llegue al LLM, para no depender solo de guardrails de salida.

## Criterios de aceptación

- [ ] Entrada sospechosa marcada y registrada (auditoría).
- [ ] `/stop` es determinista (regla, no LLM) y corta con `consent_status=withdrawn`.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas para v2 (aprendido en v1)

Este guardrail nunca se construyó en v1 (quedó P1, sin fecha) y sigue siendo el gap de seguridad real más señalado en su retrospectiva. Si el equipo tiene margen, es el candidato más claro para subir de prioridad en v2.
