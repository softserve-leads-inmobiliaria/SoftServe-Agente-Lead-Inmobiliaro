## Historia de usuario

Como orquestador, quiero que `search_properties`/`get_property` consulten Postgres real, para dejar de depender del catalog en memoria.

## Criterios de aceptación

- [ ] Contract tests en verde contra la implementación real.
- [ ] Cualquier resolución de ruta usa `db.repo_root` (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §2) — nunca un `Path.parents[N]` indexado a mano en este módulo.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.

## Notas de diseño

Usar `db/repo_root.py` desde la primera vez que haga falta resolver la ruta del repo: una copia local de esa lógica es como se multiplica el bug de indexar `Path.parents` sin filtrar.
