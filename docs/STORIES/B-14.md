# B-14 — Notas de voz transcritas

**Épica:** E2 · Canal y borde  
**Prioridad:** P2 · **Puntos:** 3 · **Track:** B  
**Depende de:** —

## Historia de usuario

Como lead, quiero mandar una nota de voz en vez de escribir, para contestar más rápido.

## Criterios de aceptación

- [ ] Entrada en `decisions.md` con el servicio de transcripción elegido.
- [ ] La nota de voz se transcribe a texto antes del guardrail de entrada, y a partir de ahí sigue el flujo normal.
- [ ] El audio no se guarda; lo que queda en el historial es el texto filtrado, como con cualquier mensaje.
- [ ] Notas más largas que un límite configurable se rechazan con un mensaje que pide escribir.
- [ ] Si la transcripción falla, se le pide al lead que lo escriba.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.
- [ ] Verificado en vivo en Telegram.
