# A-5 — Guardrail de salida — factualidad

**Épica:** E1 · Motor del agente  
**Prioridad:** P0 · **Puntos:** 3 · **Track:** A  
**Depende de:** A-4

## Historia de usuario

Como agencia, quiero que ningún número (precio, m², recámaras, etc.) que el agente mencione pueda inventarse, para no exponer a la agencia a información falsa.

## Criterios de aceptación

- [ ] Todo número/estado en la respuesta candidata existe literalmente en `last_tool_results` del turno; si no, bloquea.
- [ ] 1er fallo regenera con instrucción explícita; 2do fallo degrada ofreciendo un asesor.
- [ ] **Gold set de ≥30 preguntas como *gate* de CI construido en esta misma historia**, no como historia separada y posterior.

## Definition of Done

- [ ] Código en `main` vía PR revisado por al menos otra persona del equipo (idealmente quien consume el contrato/módulo desde el otro lado).
- [ ] Suite de tests del servicio/paquete afectado en verde en CI.
- [ ] Ningún *contract test* roto (`tests/contracts/`).
- [ ] Estado de la historia actualizado en GitHub Issues/Project — nunca en este archivo (ver `docs/ESTRUCTURA-DEL-PROYECTO.md` §5).
- [ ] Si la historia introduce o cambia una decisión de arquitectura, tiene su entrada correspondiente en `docs/DECISIONS/decisions.md`.
- [ ] Gold set en verde al 100% en CI.

## Notas para v2 (aprendido en v1)

En v1 el guardrail (A-5/DT-28) y su prueba de regresión (C-7) fueron historias separadas en el tiempo — construir un guardrail sin su gold set desde el día 1 es exactamente el tipo de deuda que v1 pagó por partes. Fusionarlas para v2.
